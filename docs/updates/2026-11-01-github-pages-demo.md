# 2026-11-01 GitHub Pages 面试演示

公开演示地址：https://liqingqing001.github.io/noval-agent/

## 演示内容

按用户指定，公开示例选用《灵石起源》。从本地 SQLite 只读提取该书 17 章正文、6 个人物、3 条世界观及 23 条大纲；没有伏笔记录。原始数据库不提交。快照仅包含作品字段，排除账号、邮箱、密码哈希、API Key、个人提示词、对话历史和封面地址；所有数据库 ID 均替换为演示专用 ID。

访客无需登录即可编辑正文、查看大纲、人物和世界观，以及导出 TXT、Markdown、Word。作品修改只保存在当前访问者浏览器，刷新保留，可通过“恢复示例”清除演示作品并重新载入快照。恢复不会修改原数据库，也不会删除访客的模型配置。

## AI 与边界

- 未配置模型时提供明确标注的示例文字回放，使用该书已有开篇，展示流式显示效果，不生成新内容、不消耗额度、不写入正文。
- 用户主动填写自己的模型 API 后，使用现有真实模型接口。费用归用户的模型账户，浏览器直连仍取决于服务商的 CORS 与网络支持。
- 公开演示没有云端账号、云同步或后端数据库服务。页面始终显示本机保存说明，不伪造云端登录状态。
- 作品、模型设置和登录缓存采用独立的 demo 存储命名空间。业务 API 层阻止演示构建请求本地后端，访客不会访问自己的 localhost:3001。

## 构建发布

新增 GitHub Actions 工作流 `.github/workflows/pages.yml`，main 更新或手动触发后执行：安装依赖、运行演示数据与编辑器/模型/同步测试、构建前端、上传 Pages 静态产物并发布。

Pages 构建设置 `VITE_DEMO_MODE=true`、`VITE_BASE_PATH=/noval-agent/`；默认本机开发及普通构建保持原登录与后端模式。使用 Node 24，安装时跳过原生后端脚本，Pages 不运行 Node 服务或 SQLite。

GitHub 仓库设置中的 Pages 发布来源使用 GitHub Actions。所有工作流 action 固定到官方示例中的提交版本。工作流仅拥有读取代码、写入 Pages 和签发部署身份的权限，不注入任何模型密钥。

首次云端安装发现旧 lockfile 仍将前端 workspace 标记为 novel-agent，而 package.json 已命名 frontend。本次只修复该 workspace 名称及链接，使 npm ci 可在干净环境解析前端，不混入本地其他依赖变动。

## 验证

演示数据测试验证书名、17 章正文、作品归属、字段脱敏及 ID 重映射。生产构建浏览器验证无需登录、真实示例、导航、示例回放、本机保存与刷新、TXT 下载、恢复示例、可选模型设置、普通存储隔离及无后端请求。编辑器、模型和同步回归测试继续执行。

源码中公开的作品快照及 Pages 网页都可被访问和下载；以后更新示例时应仅导出用户明确指定的作品。部署记录以 GitHub Actions 与 Pages 最终访问检查为准。
