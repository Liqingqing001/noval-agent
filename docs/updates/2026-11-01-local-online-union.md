# 本地与 GitHub 功能并集合并

## 范围

本次把此前保留在工作区的功能与已经发布的远程版本统一到 `main`。原始本地差异已备份，合并保留两边有效能力；私有账号口令、环境变量、本地数据库和临时测试文件不公开。

| 功能 | 合并结果 |
| --- | --- |
| 模型配置 | 保留多协议、第三方中转、连接测试与自定义参数 |
| AI 快捷操作 | 同时保留生成大纲、优化大纲、续写当前章节、续写一章、续写三章、检查章节 |
| 上下文 | 合并时间线提醒；章节检查真正发送最近最多五章正文；字数范围支持阿拉伯数字和中文数字，不再把范围上限当成最低字数 |
| 对话显示 | 保留长回复折叠、生成状态、停止生成、同步结果和重试；新增 GFM 表格显示及水平滚动 |
| 分卷大纲 | 保留卷拖拽与收起展开、状态手动选择、关联章节自动完成；修复新建卷即时归属、重复同步和未分卷排序 |
| 状态同步 | 完整章节列表标签可更新写作状态；仅在标题唯一、同一本书时写入，不执行代码块示例或未闭合列表，反馈显示实际状态更新数 |
| 精准修改 | 保留原文匹配、歧义拒绝、顺序执行和重试保护 |
| 编辑导出 | 保留正文排版、空行整理、保存保护及整本/单章 TXT、Markdown、Word 导出 |
| 手机与教程 | 保留底部工作区切换、可收起目录、设置内教程与完整第一章演示回放 |
| 后端更新 | 合并更新时间字段过滤，避免前端毫秒时间戳直接进入 Prisma 更新 |
| 工程与文档 | 同步依赖及锁文件、架构、开发记录和面试说明；删除已过时的首次建仓说明 `1.md` |

## 修正合并中发现的问题

1. 原本地快捷操作覆盖了远程快捷操作，现改为六项并存。
2. 章节大纲引用新卷时，旧 store 快照找不到刚创建的卷，导致章被归入未分卷。现在直接使用创建返回的卷，并在每次写入前读取最新状态。
3. 原字数提取会把 `3000-4000字` 误读成 `4000字`，也会给大纲生成或检查章节附加正文篇幅要求。现在保持用户指定范围，检查和大纲请求不附加默认正文长度。
4. 原「检查最近五章」仅附带三章正文，现按检查范围传入最多五章。
5. 状态同步只接受完整闭合列表，避免把示例、未完成输出或跨卷同名标题误当成确定指令。该状态记录不代表模型已生成对应正文。

## 功能一致性的边界

完整应用与 Pages 演示使用同一份创作组件、模型服务和解析代码。配置有效后，Pages 同样使用真实的 `AgentPanel`，未配置时只展示明确标注的示例回放。

Pages 是静态部署，本身不运行 Express、Prisma 或数据库：因此账号登录、云端保存只在已运行后端的完整应用中提供。演示版使用独立浏览器存储、免登录和公开样本；用户数据、密钥及后端数据库不做公开同步。这是明确的部署边界，而不是维护两套创作功能。

第三方 API 的浏览器跨域许可仍由接口服务决定；此次合并不声称修复外部中转平台的 CORS 设置。

## 验证与防止再次分叉

- 前后端 TypeScript 构建、普通应用构建、Pages 演示构建。
- 从独立空目录执行 `npm ci --ignore-scripts` 安装锁定依赖并完成双模式构建，排除已有依赖掩盖构建问题。
- 示例、导出、模型、结构化同步和写作上下文共 74 项单元回归通过。
- 独立 SQLite 测试库、随机测试账号及独立后端端口验证小说、章节、世界观、大纲和伏笔更新，传入前端毫秒时间戳时仍正确保存内容且保留数据库创建时间；不连接用户实际数据库。
- `packages/frontend/tests/featureParity.browser.cjs` 对两种构建执行相同检查：390 px 手机和 1680 px 电脑；六项快捷操作、请求上下文、GFM 表格、写作状态、电脑分卷拖拽和 Word 下载。模型请求和账号后端在独立测试上下文中模拟，不使用实际账号或产生 API 费用。
- Pages 发布工作流先验证普通应用，再验证演示版；任一模式检查失败均停止发布。
- `AGENTS.md` 增加功能取并集及发布后检查规则。每次完成更新后核对工作区、远程提交和 Pages 部署，避免未说明的长期差异。
- 公开推送前使用经官方 SHA256 校验的 Gitleaks 扫描暂存差异，默认规则及中文账号口令规则均无发现；曾含私有账号的说明文件已恢复到原有公开版本，不提交私有内容。

## 本机回归

```powershell
npm ci
npm run db:generate
npm run test:writing
npm run test:sync

$env:VITE_DEMO_MODE='false'
$env:VITE_BASE_PATH='/'
npm run build
$env:PARITY_MODE='full'
node packages/frontend/tests/featureParity.browser.cjs

$env:VITE_DEMO_MODE='true'
$env:VITE_BASE_PATH='/noval-agent/'
npm run build:frontend
$env:PARITY_MODE='demo'
node packages/frontend/tests/featureParity.browser.cjs
```

运行浏览器回归前，可执行 `npx playwright install chromium`；也可通过 `PLAYWRIGHT_MODULE` 与 `CHROME_PATH` 指定已有安装。脚本默认启动和关闭自己的 5182 端口预览；设置 `PARITY_URL` 可验证已运行的本地或线上地址。
