# 版本历史、全书一致性检查与人物状态时间线

入口是书架导航「创作检查」或作品顶部「检查」，依次提供「版本历史」「全书一致性检查」「人物状态时间线」。普通应用与 Pages 采用相同组件。手机端使用可横向滚动的分类栏和纵向卡片，保留书架、作品及 AI 助手原有入口。

## 章节版本历史

从本次更新开始，章节标题、正文改动与删除前自动记录旧稿，包括编辑器改稿和 AI 写入；已有旧稿不会伪造出过去的编辑历史。连续自动保存合并为时间窗口内的记录，避免逐字产生版本；可另存命名版本，比较历史与当前内容，查看完整正文。

恢复前先保存当前版本，再通过已有章节保存流程写回。已删除章节可从同书历史恢复，关联标识随服务器分配的新 ID 更新。恢复不执行历史正文中可能出现的 AI 指令，也不改其他章节、人物或世界观。这里的版本范围是章节标题与正文，不是整个数据库的时间点备份。

版本保存在浏览器 IndexedDB，并按普通应用账号与 Pages 模式隔离；普通应用恢复后的当前章节仍走原有 API 保存。每章保留最多 50 个版本，优先淘汰普通自动记录，总正文容量设有限制。保存失败会显示提示，未保存的资料可导出备份并重试。浏览器数据被清除或更换设备后无法从本机历史恢复，重要稿件仍应另行导出。

## 全书一致性检查

本地检查无需模型，核对章节、人物关系、大纲关联和伏笔等结构问题。每条问题附上定位与说明，可跳到章节，并由作者标记处理状态。结构检查未发现问题不代表情节语义完全一致。

AI 检查需自行配置模型，并主动确认检查范围后开始。完整正文分批提交，显示覆盖范围、进度与未完成任务；批次失败或取消后可主动继续，已完成缓存不重复请求。单次主动任务最多调用 40 次，达到后保留进度，需重新确认继续。检查还会利用人物、世界观和大纲信息，以及分批提取的事实，帮助发现跨章节矛盾。长文分批、模型能力与事实摘要会限制检查效果，不宣称已经穷尽全部矛盾。

模型报告中的章节和原文引用会在本机核对；无效引用不能冒充已验证证据。建议只供审阅，不自动修改小说。报告记录源稿版本，正文或设定变动后提示结果过期，需重新检查。检查任务与处理状态保存在当前浏览器，可导出报告；未完成任务不会显示为全书检查通过。

## 人物状态时间线

选择人物与章节，记录故事时间、地点、身体状态、情绪、已知信息、关系变化、物品和补充说明。事件依照当前章节顺序展示，支持编辑、删除和跳转原文。手工维护的状态可以没有引用，但界面会区分缺少依据、引用匹配、原文已改和章节已删除等情况。

可主动让 AI 从选定章节提取指定人物的变化。提取内容先作为建议展示，引用需匹配当前原文，再由作者选择保存；模型不会直接覆盖人物档案或时间线。章节修改后，旧依据标为待复核。时间线同样保存在当前浏览器并按账号、模式及作品隔离。

## AI 调用与验证

全书检查与人物提取都经过统一 ModelService，计入「设置 → 调用与预算」，沿用预算提醒、发送前拦截、取消和用量来源标记；本地检查、版本比较、手工时间线不产生模型费用。检查范围确认用于说明实际会提交的作品内容与预计批次，不会自动启动付费任务。

```sh
npm run test:review
npm run test:review-browser
```

单元与模拟模型浏览器测试覆盖版本保存和恢复、跨作品隔离、完整范围与引用核对、失败继续、报告过期、时间线状态维护，以及普通应用、Pages 和手机布局。测试不调用付费模型。
