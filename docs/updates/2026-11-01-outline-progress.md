# 大纲写作状态自动关联与修复

## 原因

此前「已完成」主要由 AI 整章同步、手动关联章节和显式状态指令触发。手工正文保存、先写正文后建大纲、旧数据漏关联，以及云端临时 ID 替换，都可能让已经写好的章节仍显示「待写作」。已有完成状态也可能没有正确保存正文关联。

## 统一触发规则

| 情况 | 自动模式行为 |
| --- | --- |
| 正文新增、修改或保存 | 已关联且有可见正文时标记已完成；不依赖可能过期的 wordCount |
| 清空正文 | 回到待写作；空富文本、空白、空格实体和不可见字符不算正文 |
| 删除正文 | 清除关联并回到待写作 |
| 先写正文后创建大纲 | 同一本书中，编号规范化后标题双方唯一时自动关联 |
| 打开旧书、切换面板、成功拉取完整后端数据 | 补齐可确定的正文关联和自动状态 |
| 用户点击重新识别正文状态 | 检查当前作品，显示结果；不猜测同名章节 |
| 同名章节或同名大纲不唯一 | 保持现状，编辑大纲手动选择关联章节 |
| 云端创建响应延迟或先后顺序不同 | 正文、大纲替换为服务端 ID 后修复关联，保留最新正文和状态模式 |

「已完成」仅表示已有保存正文，不代表达标目标字数、剧情完整或校稿通过。模型回复中断但没有写入正文时，不会因收到半段回复就标记完成。

## 手动控制

- 编辑章节大纲，点击「待写作 / 已完成」后保存，进入手动模式；后续保存正文、刷新和重新识别均保留该选择。
- 点击「按正文自动识别」并保存，恢复自动模式。
- 显式章节列表状态指令采用手动模式，避免与自动识别相互覆盖。
- 关联一个空章节不会被误判为已完成。已有明确关联在章节改名后继续有效。
- 普通应用与 Pages 共用同一套 store 规则；Pages 仍只保存访问者浏览器中的状态。

## 数据与迁移

大纲增加 `statusMode`，默认 `auto`，手动选择为 `manual`。完整应用通过 Prisma 保存此字段，迁移导入会保留手动模式。

补齐分卷字段的历史迁移，以及新增状态模式的增量迁移；空库可顺序执行全部迁移。本机旧库已有角色、分卷字段和索引但缺少迁移记录，已先进行 SQLite 一致性备份、核实列和索引后补记迁移，再执行新增列。原有七张业务表的全部行和原字段值已与备份逐项比对一致。

其他已有数据库应先备份、检查实际结构与 `prisma migrate status`；只有确认旧迁移已实际生效后才能补记，不能盲目重跑改表或执行 reset。新库/已正确维护迁移的部署可运行：

```powershell
npm run db:generate
npx prisma migrate deploy --schema packages/backend/prisma/schema.prisma
```

## 验证

- 新增 `test:progress`：空正文、标题规范化、同书隔离、同名拒绝、关联改名、清空/删除、先写正文后建大纲、手动覆盖、恢复自动、云端 ID 与响应顺序回归。
- 双模式浏览器回归新增正文保存、清空、手动状态保留、恢复自动和刷新持久化检查，覆盖手机及电脑。
- 发布工作流验证空数据库迁移，普通版与演示版均通过才发布。
- 使用独立测试库和模拟模型接口验证，不使用真实 API、不修改公开示例源文件。
