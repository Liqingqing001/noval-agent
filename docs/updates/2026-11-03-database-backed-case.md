# 完本案例入库并使用现有产品界面展示

## 本次修正

先前 `/book/` 是独立静态阅读站，并未把小说资料写入项目数据库。本次按用户明确要求将已有小说写入 SQLite，再从数据库查询导出公开数据，由现有产品组件展示。不伪造通过 AI 对话创作的过程或聊天记录。

## 实际数据库内容

项目数据库：`packages/backend/prisma/dev.db`，案例小说 ID：`case-tide-remembers`。

| 业务表 | 本书记录数 | 内容 |
| --- | ---: | --- |
| Novel | 1 | 《潮汐替人记得》，completed，60,720 正文汉字，书封路径 |
| Chapter | 40 | 全部正文，按 sequence 0—39 排序，含明确完本结尾 |
| Character | 8 | 人物描述、外观、性格、背景、角色定位与初登场章节 |
| WorldSetting | 9 | 六组世界规则、时间线、人物群像与创作说明 |
| PlotCard | 45 | 五卷及四十章细纲，volumeId / chapterId 关联完整 |
| Foreshadowing | 8 | 伏笔内容及埋设／回收章节和大纲关联 |

初次检查时库中没有账号和小说，因此创建专用、不可登录的示例所有者。已有其他用户或作品时不删除；多个用户且无法唯一确定所有者时，脚本要求指定 `--owner-id`。种子 ID 与其他标题冲突则拒绝覆盖。

此库有一个历史失败迁移：卷大纲字段与索引实际已存在，迁移记录却失败。本次先核对表结构，仅将已完整落地的迁移 resolve 为 applied，再应用已有 statusMode 迁移。没有 reset 或清库。

## 导入和导出

```bash
npm run demo:import
npm run demo:check
```

`demo:import` 从已有四十章正文及设定源文件建立记录，在数据库事务中幂等写入，然后重新查询数据库，导出 `packages/frontend/src/demo/tideMemory.json`。它不是直接把正文文件改名为前端 fixture。

`demo:check` 只读检查实际数据库、正文和公开快照是否一致。可用 `--database-url`、`--owner-id`、`--snapshot` 指定目标；`DATABASE_URL` 优先于默认项目库。导入需要已完成项目迁移的 SQLite 库，不会自动 reset。

数据库与凭据不提交 Git。仓库提交导入程序及经过字段白名单筛选的公开快照，快照不含 User、密码、邮箱、API Key 或 Agent 配置，业务 ID 转成 `demo-tide-*`。

## Pages 的边界

GitHub Pages 只托管静态文件，不能运行 SQLite 或 Express。公开页面读取**从数据库导出的快照**，使用与普通应用相同的书架、人物、世界观、大纲和章节组件；不是在 Pages 上连接开发数据库。访问者的编辑仍只保存在各自浏览器，不回写项目库。

默认和恢复示例仅含这一本。未修改过的旧《灵石起源》示例自动升级；浏览器中已有自创作品、内容修改、聊天或人物画布资料时不静默清空，可点「恢复本书案例」明确替换。

原 `/book/` 地址现在跳转到产品工作台，不再展示独立阅读站。正文与图片源文件仍保留，供数据库导入、下载和校验使用；旧阅读站 JS / CSS 已移除。

书封由 Novel.cover 读取；人物群像通过数据库 WorldSetting 中的 Markdown 图片引用，在共享世界观卡片中显示。Markdown 不执行原始 HTML，图片和链接经过安全地址处理。

## 发布和验证
