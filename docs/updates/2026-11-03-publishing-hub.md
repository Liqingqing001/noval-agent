# 发布中心与平台政策调研

## 入口与使用

- 书架导航新增「发布中心」，没有作品也能查看平台。
- 作品顶部在原「导出」旁增加「发布」；原导出和创作功能保留。
- 普通应用与 GitHub Pages 演示使用同一个懒加载组件，不需要模型调用。
- 十四个平台 / 渠道，支持名称、读者类型、地区和 AI 政策筛选。
- 每个平台显示官方入口、投稿路径、文件能力、API 调研结论，以及正文、辅助、图片、签约四部分 AI 策略。
- 来源列明官方属性、正文 / 索引 / 访问受限状态、可核实日期与短引文。无法确定的规则保留「待核实」。

[完整调研报告](../research/publishing-platforms.md) 由结构化目录生成，发布中心可下载同一份内容。

## 第一版实际做到哪一步

已可用：

1. 按作品隔离并按章节顺序整理材料。
2. 复制书名、简介、单章纯文本正文；剪贴板权限不可用时显示可选择的文本框。
3. 复用现有 TXT / Markdown / Word 导出，不另写一套正文解析。
4. 下载投稿资料，包含简介、章节清单、目标入口和作者自己填写的 AI 正文 / 图片使用说明。默认「尚未确认」，不会自动推断纯人工，也不修改正文。
5. GitHub Pages 渠道可生成带目录、手机排版、HTML 转义、无外部脚本依赖的单文件阅读页，供作者自行部署。
6. 用户主动打开官方作者后台，按该平台规则预览、声明和提交。

尚未实现：账号授权、远端建书 / 上传、审核同步、定时发布、签约和收益管理。所有目录项 `automatic: false`。下载或打开后台不会变成「已发布」。未采集平台 Cookie、密码或验证码。

## 调研边界

- 阅文：编辑内投 / 签约页的 AI 生成限制明确；不能扩大为所有站点全部行为的统一结论。合作方读书 / 读章节 API 不等于作者发布 API。
- 番茄：官方 AI 写作、插图工具存在；并不自动证明整本生成稿可以签约或无需声明。
- 晋江：原页可访问性和索引证据分别保留，不用搜索摘要冒充完整现行规则。
- AO3：fanworks 范围与非商业限制是重要边界，不是通用商业发布渠道。
- KDP：生成文本、图片与翻译需告知，辅助不同；Select 排他与中文语言支持另行确认。
- Royal Road：按当前 Content Guidelines 区分 AI 标签；旧公告与当前细则不一致时不沿用旧文。
- Wattpad：部分正文访问错误，官方索引不是完整正文；未确认通用 AI 文本准入 / 披露政策。
- 其他国内平台保留入口和已找到的公开指南，专门 AI 条款未确认则明确标注。

## 文件与维护

- `packages/frontend/src/data/publishingPlatforms.json` 是调研单一来源。
- `npm run publication:report` 同步生成仓库报告和 Pages 可下载报告。
- `PublicationHub.tsx` 展示目录与本机材料操作；`publication.ts` 负责可测试的材料生成。
- 本机 HTML 只导出正文和简介，不擅自嵌入书架图片、账号信息或 Agent 配置。
- 规则变更时更新来源、访问状态、核查日期和适用范围，而不是只改一个允许 / 禁止标签。

## 验证

- 投稿资料的默认未知状态、跨书隔离、章节排序、HTML 转义及空章节处理单元测试。
- 普通应用和演示两种构建，390 / 1680 px 验证两处入口、平台筛选、材料下载、复制 / 手动回退、单文件阅读页、无远端投稿及无跨书内容。
- 原有编辑导出、演示、同步、章节选择和完整应用功能回归；Pages CI 加入两种环境的发布中心回归。
- 前端构建保留原有 Vite 配置兼容与大 chunk 提示，未改依赖或锁文件。
