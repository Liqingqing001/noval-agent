# 2026-10-28：修复 AI 批量修改与章节同步

## 问题与结果

用户反馈连续的 `【修改】` 指令没有正确更新章节。原实现依赖换行分隔“原内容”和“新内容”，同一行输出会将两者混读；章节编辑器保存 HTML，AI 引用可见文字时也可能匹配不到。部分目标使用第一个同名记录，其他面板的修改还存在未匹配原文就计成功、角色字段被整段覆盖的问题。

本次将修改解析、正文匹配、执行反馈拆分处理。每条指令得到真实执行结果；成功修改保留，失败条目单独说明原因，不推断或修改其他章节。

## 修改规则

- 支持同一行、分行、Windows 换行、中文或英文冒号，以及 Markdown 字段标签。
- 每条必须有完整的开始和结束标签，并提供目标、标题、原内容、新内容。角色须提供姓名和可编辑字段。
- 缺少开始标签、结束标签或字段时不猜测目标；损坏的一条不会吞掉后续完整指令。
- 代码块、引用和介绍性的指令示例不作为修改执行。修改正文内引用的章节、删除等标签不会另行执行。
- 限定当前小说，先查准确标题，再兼容标题开头的“第 N 章”；不会删掉“四个小时”等标题中的数字，也不会使用标题包含关系误定位。
- 同名目标多于一个或原文出现多次时拒绝自动选择，提示补充唯一标题或更长的原文。
- 按回复顺序在暂存版本上应用修改，同一条目合并为一次保存。后续指令引用前面已经修改的内容时可继续执行。
- 富文本按可见文字定位，可跨加粗片段和段落；保留范围之外的排版。新内容以文字插入，不解释为 HTML。
- 仅兼容空白和中英文单双引号差异，不使用语义近似或数字近似匹配，避免把时间、车牌等改错。
- 已包含新内容时不重复写入，包含原文字串的新内容也不会在重试时越改越长。
- 角色、大纲、卷、世界观同样校验原文，只修改匹配部分，不再用片段覆盖整段字段。角色可修改性格、背景、外貌和描述；不接受 ID 等任意字段。

推荐格式：

```text
【修改】
目标：章节
标题：四个小时
原内容：五点二十分，稿子才发出去，发给市里的主管部门。
新内容：三点五十五分，稿子才发出去，发给市里的主管部门。
【/修改】
```

## 对话与编辑器

- 对话新增“查看修改结果”，逐条展示已修改、已包含新内容或未执行及原因；有失败时整体显示警告，不再只显示成功条数。
- 修改回复提供对应面板入口；旧的完整修改回复可以通过“重新同步到面板”重试。
- 重试只额外开放经过校验的修改，不重放删除、全量替换、插入、合并、拆分或排序命令。
- 同时包含完整章节和修改时，先同步章节，再应用修改，避免章节同步把修改覆盖。
- 编辑器收到外部正文更新时取消旧版本的延迟保存；外部清空正文也会同步显示。
- 同步状态明确指向本地面板。现有 store 的后台上传仍为异步处理，本次未将其改为云端持久化成功确认。

## 用户示例的处理

以“四个小时”和“数”两章建立临时测试数据：

1. 从走出北门改为观察舱睁眼。
2. 从五点二十分发稿改为三点五十五分。
3. 将指定车牌片段从京 A 改为南 A。
4. 将走廊怪叫片段改为观察北区天色。
5. 将喊到全校改为喊住全场。
6. 将停电快四十分钟改为快二十分钟。

完整六条均可分别写入对应章节。用户粘贴内容的第一条缺少开头和目标信息，按原样输入时明确报告第一条未执行，后续五条正常执行。旁边“第 1 章如果也有就改”等说明不会被当作额外修改；跨章修改须逐章输出独立指令。
