# 手机工作区适配

## 问题与原因

手机访问时，书架、作品与 AI 助手仍按电脑三栏排列。书架、AI 助手和章节目录都有固定宽度，屏幕不足时，中间作品面板被压缩到几乎不可见。正文数据没有丢失。

## 本次改动

- 小于 1280 px 的屏幕使用单面板布局，底部提供「书架 / 作品 / AI 助手」切换，首次进入默认显示作品。切换只隐藏面板，保留编辑器和助手实例，避免切换时清空编辑、停止生成或重置回放。
- 从书架选择小说、人物、世界观、大纲或设置，以及从演示助手打开作品或 API 设置时，自动显示对应作品面板；重复选择当前视图同样有效。
- 小于 768 px 的手机屏幕，以及高度不超过 500 px 的窄屏横屏，章节目录改为按钮展开。选中章节后自动返回正文，也可点击「返回正文」收起目录。
- 手机标题、工具栏、稿纸边距与演示提示采用紧凑排版，简介可在大纲中查看；大纲简介区域可独立滚动，避免长简介占满章节大纲区域。横屏进一步收紧顶部提示和底部导航高度。
- 使用动态视口高度 `100dvh`，为底部导航预留设备安全区域；电脑仍可拖动调整面板宽度，并限制侧栏占比，避免保存的过大宽度挤掉正文。
- 切换面板和导航前立即保存当前编辑内容，演示数据仍只保存在访问者自己的浏览器。

## 验证

- 前端 TypeScript 检查与演示构建通过。
- Chrome 浏览器回归覆盖 320×667、375×667、390×844、844×390、768×1024、1024×768、1280×800、1680×1050。
- 检查默认正文可见、无页面水平溢出、底部导航可触达、章节选择、人物/世界观/大纲/设置导航、重复选择当前视图、切换后编辑保存、刷新后保留、回放持续、TXT 下载、排版设置和导出弹窗边界，以及电脑/手机尺寸切换。
- 已渲染检查手机、横屏和电脑截图。使用 Chrome 模拟尺寸验证，未使用实体手机或 iOS Safari，浏览器键盘及安全区域表现仍需真实设备体验。

## 浏览器回归命令

新增 `packages/frontend/tests/mobileLayout.browser.cjs`。先以 `VITE_DEMO_MODE=true`、`VITE_BASE_PATH=/noval-agent/` 构建并在 5181 端口预览，再运行：

```powershell
# 环境需已有 Playwright；也可用 PLAYWRIGHT_MODULE 指定现有模块的绝对路径。
# CHROME_PATH 可指定已安装的 Chrome；省略时使用 Playwright 默认 Chromium。
node packages/frontend/tests/mobileLayout.browser.cjs
```

可设置 `DEMO_URL` 检查公网演示，设置 `SCREENSHOT_DIR` 保存各尺寸截图。测试使用独立浏览器上下文，编辑仅影响测试上下文中的示例，不覆盖用户已有作品，也不调用真实模型。

更新推送至 `main` 后沿用现有 GitHub Pages 工作流自动发布。
