# 人物关系画布首版实施范围

日期：2026-11-02。根据用户提出的「像 Obsidian 白板一样，人物头像之间连线，点击头像打开人物面板，编辑当前状态」，在人物模块新增关系画布，保留完整人物列表和既有人物档案编辑流程。

## 交互

人物默认以头像节点展示，没有上传图片时使用姓名文字徽章。拖动节点调整位置，拖动空白平移，滚轮或加减按钮缩放；提供适应画布、自动排布和展开专注画布，Esc 退出专注。键盘聚焦人物后可用方向键移动，Shift 加大步长。手机支持单指拖动、点按人物和按钮缩放，不实现双指缩放手势。

「添加关系」选择同一作品中的起点、终点，填写关系名称、分类、方向和备注。亲属 / 师承、同盟、敌对及其他使用不同线色。多个关系通过曲线区分，点击标签编辑或删除；不允许自连线和同方向同名称的重复关系。系统不从姓名、简介或性别标签自动猜测关系，初始无关系时需用户手动添加。

点击人物打开详情侧栏，显示简介、性格、外貌及背景；可继续打开原有编辑器修改人物档案。侧栏支持上传 PNG、JPEG、WebP 头像，最多 5 MiB；在浏览器裁成 160×160 JPEG 后保存，不上传外部图片服务。手机侧栏覆盖画布区域，关闭后返回关系图。

状态字段包含生死状态、当前位置、伤势、当前目标、持有物品、备注及「截至章节」。可点击保存；通过应用导航切换功能或人物列表时也会提交本次状态。关闭侧栏或切换人物时，尚未保存的编辑需明确决定是否放弃。浏览器关闭前仍应确认保存状态，未完成事务不保证能在关闭后继续。

状态是作者手动维护的一份快照，「截至章节」只是该记录的时间标注，不是自动计算的逐章历史。删除关联章节后显示待复核，不自动推断新状态。本版不将这些快照自动注入 AI 提示词，避免重写早期章节时泄露后续生死、伤势或秘密；也不自动改变正文。

## 数据和边界

人物档案继续使用现有作品存储与后端接口；新增头像、位置、关系、状态单独保存在浏览器 IndexedDB，以环境、用户和作品为命名空间。普通应用与 Pages 使用同一画布实现；这部分扩展数据均不跨设备同步，没有新增后端表或迁移。

人物云端创建成功后，前端临时编号可能变成服务器编号。衔接时同步迁移节点、头像、状态、位置、连线端点和当前选择，保留正在编辑的状态草稿，避免连线断开或状态丢失。缺失人物对应的旧连线不会画到其他人物上；从画布删除人物时同步清理其本地关联。

每份画布允许最多 2000 份节点扩展、5000 条关系、约 800 万序列化字符，受实际浏览器空间约束。画布最多同时展示 500 位人物，搜索在全部人物中匹配后再截取显示；其余仍可通过列表访问。视野坐标范围为 0–20000，缩放为 5%–220%，不是无限白板。

保存采用按序事务并跳过已被后续编辑替代的等待写入。失败保留页面改动并显示重试入口，不声称保存成功；无法读取时不自动覆盖原记录。可导出 UTF-8 JSON，包含人物编号、姓名及画布扩展数据；本版没有 JSON 导入、PNG 导出或多人协作入口。

## 验收

新增画布数据约束与几何单元测试。完整应用和 Pages 均运行手机 390px、桌面 1680px 浏览器回归，覆盖关系增改删与自连线校验、触屏点按、状态保存、头像处理、拖动和键盘移动、平移缩放、专注模式、搜索、导出、刷新恢复、原列表保留、切换功能保存，以及云端编号变更后状态草稿与关系端点保留。所有后端数据均模拟，不操作用户真实作品。
