## 1 评审摘要与决策建议

建议为 NovelAgent 新增“参考创作”工作台，支持上传书籍或文章，拆解结构、故事走向和文风，将经用户确认的分析转成新大纲及短文或样章，并导入已有创作模块。核心价值是缩短从参考阅读到独立创作的路径，提高方法复用和草稿可用性。

推荐有条件立项：先验证“分析可信、方法可迁移、草稿有用”三个假设，再扩大投入。MVP 同时覆盖故事类书籍拆解和单篇文章分析；长书分析采用异步任务，生成限于新大纲和单篇文章或单章样稿。非虚构整书深度拆解、多作品融合、整本小说连续生成和平台自动采集暂缓。

本次评审需明确：①是否认可主用户与范围；②是否接受服务端异步分析依赖；③试测成本预算与模型选择；④授权、留存和删除规则；⑤质量门槛与灰度负责人。文内配额、性能和转化目标均为建议值，不代表现网能力或行业基准。

## 2 背景与现有产品约束

### 2.1 需求来源与待验证问题

需求来自用户提出的“上传一本书，拆解大纲、故事走向和文风，用于仿写；同时支持爆款文章分析”。目前缺少用户访谈、行为基线及付费验证，不以竞品存在推导需求规模。

目标问题：通用对话结果难核验；长书容易遗漏跨章关系；分析结束后仍需用户自行转写创作要求；参考设定与自己的作品混在一起；一次性生成长文的质量和成本不稳定。

以下为当前代码与项目文档观察，不代表线上服务可用性验证。

## 3 用户与任务场景

### 3.1 用户优先级

| 人群 | 典型任务 | 优先级与价值判断 |
| --- | --- | --- |
| 有稳定写作任务的小说或短篇作者 | 看懂参考书的冲突与节奏，设计自己的新故事 | 主用户；与 NovelAgent 现有能力契合 |
| 公众号、知乎等文章作者 | 从一篇参考文提取结构和表达方法，换选题创作 | 次用户；验证高频短任务价值 |
| 编辑、MCN 和品牌团队 | 多作品对比、统一风格与协作审稿 | 后续；组织权限和协作不进入 MVP |

### 3.2 用户故事

US-01：作为小说作者，我上传长书后，希望看到分章大纲、主线与人物变化，并能核验关键转折的原文。

US-02：作为文章作者，我粘贴参考文后，希望知道开头、段落和结尾各承担什么功能，并将结构应用到新选题。

US-03：作为创作者，我希望只借鉴自己选择的句式、节奏或结构，更换人物、事件和素材，得到可继续编辑的新稿。

US-04：作为已有 NovelAgent 用户，我希望将确认后的新创作导入指定作品，参考书的角色和世界观不会未经确认写入我的作品。

US-05：作为长任务用户，我离开页面、断网或任务失败后，希望知道完成范围、费用和恢复方式。

## 4 目标与范围

### 4.1 目标与非目标

产品目标：提高参考分析到有效创作的转化；降低完成同等质量初稿的时间；形成可复用的方法卡和文风卡。业务目标：验证复用与付费意愿，识别可承受的单次成功成本。

非目标：预测或保证爆款；保证全网原创；绕过电子书 DRM；自动发布；首版生成整本小说；构建公共盗版书库。图片封面、视频、音频及扫描件分析均不进入首版。

### 4.2 版本范围

| 编号 | 能力 | MVP | 后续 |
| --- | --- | --- | --- |
| R01 | TXT、DOCX、文字型 PDF、直接粘贴 | 是，中文优先 | EPUB、OCR、URL 解析 |
| R02 | 章节识别、范围确认与解析异常提示 | 是 | 批量资料管理 |
| R03 | 故事类全书与分章结构、人物、事件分析 | 是 | 非虚构整书专项分析 |
| R04 | 单篇文章结构与吸引力分析 | 是 | 跨篇对比、跨平台表现分析 |
| R05 | 文风卡、方法卡、原文定位、用户修订 | 是 | 多来源融合与团队共享 |
| R06 | 新创作简报、大纲、短文或样章 | 是 | 整本分章连续创作 |
| R07 | 导入 NovelAgent、DOCX 与 Markdown 导出 | 是 | 发布与效果回流 |

### 4.3 建议配额与计数口径

私测暂定单文件不超过 20 MiB、书籍正文不超过 30 万计数字符、文章不超过 2 万；每用户最多 1 个执行任务和 2 个排队任务。超过上限在分析前拦截，允许选择章节，不静默截断。正式配额根据压测与成本评审调整。

输入计数字符定义为 Unicode 码点中非空白字符数；不含目录、页眉页脚等已识别噪声。输入配额不等于模型 token 数。生成长度按正文非空白字符统计，不含标题、说明和结构化标签；UI 明示此口径，英文同样按字符计。

## 5 信息架构与关键交互

“参考创作”是用户级资料空间，独立于当前选中的小说。列表显示标题、类型、处理范围、任务状态、更新时间和删除入口。详情包含原文、分析、文风、创作四个页签。

桌面端使用“章节／原文—分析或新稿—依据与参数”三栏；窄屏使用页签切换，保留任务状态与主要操作。原文引用支持键盘聚焦与返回阅读位置，状态不只用颜色表达。

主流程：导入资料 → 检查解析与范围 → 查看预估消耗并开始分析 → 核验或修正 → 选择方法和文风 → 填写新创作简报 → 确认新大纲 → 生成短文或样章 → 编辑／导出／导入作品。

| 界面状态 | 用户可见信息 | 操作规则 |
| --- | --- | --- |
| 空列表 | 支持格式、上限、示例资料 | 上传或粘贴，不要求先建小说 |
| 待确认解析 | 目录、字数、异常段落与覆盖范围 | 调整边界、排除目录、确认分析 |
| 排队／处理中 | 当前阶段、已处理章节／总章数、可离开提示 | 取消；不显示虚假固定倒计时 |
| 部分完成 | 已完成与失败章节、费用和影响 | 看部分结果、重试失败章节；报告带范围标记 |
| 分析完成 | 版本、处理范围与依据 | 修订分析、保存卡片、开始新创作 |
| 新稿未达要求 | 实际长度、目标范围、截断原因 | 编辑、补写或保留；不显示可直接导入的成功态 |
| 云端同步失败 | 本地保存结果与云端错误 | 重试同步，不能重复创建章节 |
| 来源已删除 | 历史结论和引用不可访问说明 | 禁止继续检索；独立新稿仍可编辑 |

## 6 功能需求与业务规则

### 6.1 R01 至 R02 导入与解析

支持拖拽、文件选择与粘贴；校验扩展名、MIME、文件签名、大小和解压后体积，拒绝宏执行、嵌入脚本及加密文件。TXT 自动识别常见编码，失败时让用户选择编码或重传。PDF 无可提取文本时明确提示首版不支持扫描件。

解析结果保留文档版本、章节顺序、段落标识、原始页码（若有）与文本偏移。DOCX 不承诺跨设备固定页码，以章节和段落定位。章节识别采用标题层级和模式匹配，用户可合并、拆分、重命名或排除内容。

同用户同内容哈希上传时提示复用已有解析或创建独立副本，不跨用户暴露是否存在相同文件。确认范围后冻结 source_version；后续修正生成新版本，旧分析不自动变成新版本分析。

### 6.2 R03 故事类书籍分析

| 分析模块 | 必须输出的字段 | 判断约束 |
| --- | --- | --- |
| 全局概览 | 一句话梗概、主题、主线、阶段结构 | 区分文本事实与主题解释 |
| 分章大纲 | 目标、关键事件、冲突、转折、章末悬念 | 覆盖所选全部章节；无关维度可标不适用 |
| 故事走向 | 展示顺序、故事时间、事件因果、关键转折 | 倒叙和插叙不混成事实时间线 |
| 人物弧线 | 目标、阻力、动机、选择、关系与变化 | 别名合并可修订；不把推测当明确心理事实 |
| 伏笔回收 | 埋设位置、回收位置、关联解释 | 没有回收证据时标待验证，不强行配对 |
| 节奏与方法 | 冲突密度、信息释放、可迁移方法及适用条件 | 曲线为解释性判断，不包装成客观标准分 |

全局归纳基于全部已完成章节的结构化结果。漏章时只能生成“所选范围／部分范围分析”，不得声称完整全书结论。每个关键转折、人物关系和伏笔结论至少绑定一条可定位依据；跨章结论绑定多处依据。

### 6.3 R04 与 R08 文章分析及传播表现

文章分析包含目标受众、选题价值、标题承诺与正文兑现、开头钩子、逐段功能、论证链、情绪变化、结尾行动引导、可迁移结构及不适用条件。广告性内容另标转化目的；不根据正文推断真实成交或读者人口属性。

无数据时报告名为“内容吸引力分析”，不输出爆款概率或“火的原因”。用户可手填平台、发布时间、统计时间、曝光、阅读、点赞、收藏、评论、分享和账号粉丝量；原始值、录入来源与时间一起保存。

缺失值与 0 区分；数值非负，发布时间不晚于统计时间。阅读大于曝光等情况先提示口径可能不同，由用户确认，不擅自修正。曝光缺失或为 0 时不计算曝光互动率。点赞、收藏、评论、分享之和除以曝光只能命名“每次曝光互动次数”，可能超过 100%，不可解释为去重用户比例。没有同平台同口径的基准，不输出优于同类结论。

传播报告分“观察到的表现”“内容机制假设”“下次验证建议”。单篇高互动不能证明某种句式导致传播；MVP 不提供因果归因。

### 6.4 R05 证据卡与文风卡

证据卡字段：结论、事实／解释类别、source_version、chapter_id、paragraph_id、start/end 偏移、最小必要短引文、解释、用户修订状态。置信度使用“依据充分／依据有限／待验证”，不是模型自报的概率。用户修改结论保留模型原版及修订版本，不修改原文。

文风卡提取句长分布、段落长度、口语程度、视角、对话与描写比例、情绪强度、修辞、节奏和禁用表达。可计算特征由程序统计，主观特征注明解释依据。前中后段分层采样，展示覆盖章节与样本量；只选一章时只声称该章风格。

卡片可以编辑、重命名和复用，按版本绑定创作。生成采用用户选中的通用语言特征，不提供特定在世作者的精确复刻承诺；用户自有或获授权的风格样本可用于一致性辅助。方法卡描述抽象结构、功能、适用场景及迁移建议，避免复制整条具体情节链。

### 6.5 R06 创作简报与生成

简报必填新主题／故事设定、目标读者、产物类型、目标长度；可选平台、素材、人物、禁用项及文风特征。提供“借鉴结构”“应用文风”“同时使用”三个选择，并展示会传入生成的字段。

先生成可编辑新大纲。故事检查新人物、背景、目标、冲突和事件因果；文章检查新观点、论据需求与段落功能。用户确认后才生成正文。事实型内容缺证据时使用明确占位符或请求补充，不能编造采访、数字和引用。

长度范围：短文 500～5000 计数字符，样章 1000～5000；目标区间由用户输入。生成结束检查正常结束标记、长度、必填素材、关键设定与占位符。低于下限允许用户发起补写，最多 2 次，不自动无限调用；超过上限提示压缩。截断、未解决占位符和关键设定冲突均阻止“已验收”状态，但允许用户保留为未验收草稿。

相似片段检查限本次选中参考资料：程序检测连续重复与片段重合，语义模型辅助提示相似情节；短语、常用语与引用单独展示，不以单一分数判断侵权。默认提示连续相同的 30 个非空白字符片段，阈值需经评测校准。不得标注全网原创率或法律保证。

### 6.6 R07 导入现有作品与导出

分析对象与生成对象使用不同命名空间。分析阶段不得调用 autoSync 创作写入；原文中的【角色】等内容仅作为引用显示。导入界面展示目标作品、待新增条目、冲突和关联版本，默认新建，不覆盖已有数据。

导入必须由用户明确选择：新大纲映射 PlotCard；新角色映射 Character；新世界观映射 WorldSetting；正文映射 Chapter。参考作品的分析不能批量误导入。文章默认保存在独立创作草稿，不为导出强制新建 Novel。

导入使用 operation_id 与条目映射保障幂等；同名条目不等于同一实体。覆盖需逐项选择并检查 expected_revision；检测并发编辑后停止该条覆盖并保留草稿。云端确认前显示待同步，失败可按同一操作重试。导入产生清单和前版本；撤销仅处理该次操作，目标后续有修改时改为冲突处理，不直接删除。

导出 DOCX／Markdown，允许选择新稿或分析报告。报告默认包含范围、来源与版本，新稿默认不附参考原文。生成文件名经清洗；大文件异步导出，链接短时有效且鉴权。

## 7 任务状态与恢复规则

解析任务与分析任务分开保存。解析：uploaded → parsing → awaiting_confirmation；错误进入 failed，用户取消进入 cancelled。分析：queued → running → succeeded／partial／failed／cancelled；运行阶段包括分章、跨章归纳、引用校验。

创建任务需 source_version、范围、参数、幂等键和配额预留。同请求重复提交返回原任务；同一版本并发创建不同配置需各自额度。任务 worker 以租约与心跳执行，超时释放并从已提交检查点恢复，阶段结果按唯一键写入，重放不重复记账。

| 异常 | 结果与恢复 |
| --- | --- |
| 网络断开或关闭页面 | 后台继续；重连通过 task_id 恢复，不再创建任务 |
| 模型超时／限流 | 指数退避，阶段自动重试最多 2 次；仍失败显示可手动重试 |
| 单章失败 | 保留其他章节；全局结论标范围不全，允许仅重试失败章 |
| 用户取消 | 停止未派发请求，尝试取消在途请求；保留已完成片段并解释已发生消耗 |
| 配额不足／模型不可用 | 分析前拒绝或暂停派发，释放未使用预留，不暗中切换更贵模型 |
| 来源删除 | 停止相关任务、撤销索引可见性与下载权限，再异步清理 |

终态由服务端持久化后通知客户端，进度事件不是成功凭据。重新分析创建新 analysis_version；用户确认后的卡片和旧稿保留原版本绑定。

## 8 数据模型与接口边界

此节定义产品所需契约，最终表结构、队列与存储选型由技术方案评审确定，不表示这些接口已经实现。

| 实体 | 关键字段与约束 |
| --- | --- |
| ReferenceSource / SourceVersion | user_id、类型、状态、哈希、存储键、解析版本、授权确认、删除时间 |
| SourceSection | version_id、章节、顺序、段落、页码／偏移、正文哈希；偏移采用规范化文本码点 |
| AnalysisTask / TaskStage | 参数、版本、幂等键、状态、覆盖范围、租约、错误码、模型与用量、阶段 token 上限、请求预留、价格版本 |
| AnalysisReport / Evidence | 结构化结果、结论类别、来源锚点、修订版本；锚点不能跨 source_version |
| StyleCard / MethodCard | 来源版本、特征、适用范围、用户修改、卡片版本 |
| CreationDraft / DraftVersion | brief、已确认大纲、卡片快照、正文、验收状态、长度、未完成原因 |

所有资源按 user_id 校验归属，下载、事件流、导出与删除同样鉴权。写入携带版本或幂等键；错误统一返回 error_code、retryable、request_id 及可读提示。事件流断开后 GET 为权威状态，支持 last_event_id 恢复；前端不依赖连接常驻。

## 9 算法与工程依赖

处理链路为解析与规范化 → 分章事实及事件提取 → 实体别名对齐 → 全章覆盖检查 → 全局结构归纳 → 文风采样 → 引用锚点校验 → 结构化报告。检索用于证据核验和生成上下文选择，不替代全章分析。

模型输出采用 schema 校验，事实提取、文学解释和生成分别配置提示词。引用位置由程序验证文本匹配，无法定位时降级为无依据结论并阻止进入关键事实字段。记录模型、提示词、解析器及 schema 版本；模型升级需重跑冻结评测集。

长任务需要对象存储、持久化任务调度、worker、用量计量和服务端模型访问。现有 SQLite 可用于单实例验证，生产多 worker 的租约、并发写入与锁竞争须专项验证，再决定是否迁移数据库，不将迁移当作既有能力。

私测建议使用服务端托管模型并设置预算；不上传用户浏览器内保存的 API Key。若未来支持用户自备密钥执行后台任务，须单独设计密钥托管、授权与撤销，不以长期保存现有前端配置替代。

## 10 权限 隐私与内容治理

资料默认仅上传者可见，MVP 不提供公共共享或跨用户素材检索。上传时确认拥有处理该资料的权限；不支持 DRM 移除，不承诺上传即有合法授权。正式上线前由负责人员确认服务条款、投诉处理及第三方模型的数据处理条件。

默认不将原稿用于训练；产品内明确展示模型服务处理范围。业务日志仅记录标识、阶段、错误与统计值，不记录正文、密钥或完整提示词；诊断采样需脱敏且单独授权。文本作为不可信数据，不得执行其中指令、外链或工具调用。

建议保留：原稿及分析持续保存至用户删除；在线资料和索引删除在 24 小时内完成，立即撤销访问；备份最长 30 天滚动清除，删除账本防止恢复后复活。最终周期需结合基础设施和法务评审。独立新稿默认保留，删除来源前告知引用将失效；支持用户另外删除新稿。用户删除账号时覆盖全部关联数据。

## 11 非功能需求与容量假设

以下为私测目标，负载条件为 100 个同时在线用户、10 个活跃分析任务、约 70% 短文与 30% 书籍；压测后决定实例和队列容量，不能外推至更大规模。

| 项目 | 建议目标 | 测量口径与降级 |
| --- | --- | --- |
| 创建任务 API | P95 ≤2 秒 | 不含文件上传与模型调用；排队也返回 task_id |
| 短文分析 | P95 ≤90 秒 | 5000 字以内，从确认到报告可用，含排队 |
| 长书分析 | P95 ≤15 分钟 | 20 万字以内，含排队；不含人工确认与上传 |
| 状态可见 | 进度或心跳间隔 ≤10 秒 | 模型长时间无正文也显示真实阶段 |
| 长任务成功率 | ≥95% | 合法支持输入，含系统重试；用户取消单列 |
| 任务可靠性 | 恢复不丢已提交检查点 | worker 退出、断网、重复派发故障演练 |
| 可用性 | 核心 API 月度 99.5% | 5xx 和超时为失败，第三方导致的用户失败也计入 |

达到队列上限时显示预计等待区间或拒绝新增；仅在有历史估计时给等待时间。超出时延目标仍可继续执行，达到单任务硬预算则停止派发并返回部分结果，不以自动换模型掩盖降级。

## 12 商业化与成本约束

私测先验证成本和使用价值，不立即承诺订阅权益。拟采用“分析额度＋生成额度”，分析资产可复用；只修改创作简报不重复收整本分析额度。启动前展示范围、预估消耗、硬上限和取消规则。

### 12.1 成本计量与展示

任务模型成本 C_model = Σ请求（未缓存输入 token × 对应单价＋缓存读取 token × 对应单价＋缓存写入计费项＋计费输出 token × 对应单价＋其他服务商计费项）。单价统一折算到每 token，价格表保存币种、模型、版本、生效时间和上下文长度价格档位。缓存写入是否另计、推理 token 是否已包含在输出中，按服务商账单映射，不能重复计算。平台缓存折扣不等于业务结果缓存，后者命中时可以完全不发模型请求。

总任务成本还包括解析、向量化（启用时）、存储、检索和调度摊销。内部同时报告正常完成成本、含失败与重试成本和每个有效创作成本；上传字数只用于产品配额，不能直接当 token 结算。计费输出包含服务商实际计费的可见正文和推理等 token，不能只数用户看到的文字。

确认分析前展示本次范围、分析模式、预计区间、额度上限以及是否复用已有分析；完成后展示实际扣减与可复用资产。用户界面以额度和金额为主，详情可查看 token 分项。没有可靠 tokenizer 或历史样本时标“估算”，采用保守上界；不得用固定“一个汉字等于一个 token”做承诺。

### 12.2 分阶段控制输入与输出

基本原则为“原文分块提取一次，跨章使用结构化摘要，创作仅带必要信息”。禁止每个分析维度都发送整本书，禁止将全量原稿、全部报告和全部聊天历史持续追加到每一轮请求。

| 阶段 | 上下文策略 | 建议私测上限与质量约束 |
| --- | --- | --- |
| 解析、章节识别、字数、引用匹配 | 优先程序处理，不调用模型完成确定性任务 | 不消耗生成 token；复杂边界仅按需调用 |
| 章节事实与事件提取 | 按章节或场景切块；全部所选原文覆盖一次，跨块重叠单独计量 | 每请求输入 ≤12000、计费输出 ≤1200 token；字段无信息时允许为空 |
| 跨章归纳 | 仅发送分章结构化结果与必要原文证据；超过预算则分层汇总 | 每请求输入 ≤24000、计费输出 ≤4000 token；保留各级来源索引 |
| 文风分析 | 前中后分层采样，句长等统计程序计算 | 总输入 ≤16000、计费输出 ≤2000 token；明确采样范围 |
| 新大纲与正文 | 简报、选中文风卡、大纲、相关事实／片段；按需检索 | 每请求输入 ≤12000、计费输出 ≤8000 token；不足目标时不冒充合格 |
| 质量检查与补写 | 字数、标签、重复先用程序检查；模型只处理问题片段及必要上下文 | 不为局部问题重传全书；补写仍受任务余额约束 |

这些上限为可配置私测建议，不是模型窗口容量或质量保证；均包含系统提示词、模板、示例、工具 schema 和用户输入。输出上限必须映射到服务商真实的计费输出限制，不能仅限制可见正文。模型不支持可控计费上界时，不进入自动后台长任务名单。长上下文不能作为默认全量传入的理由。

提供“快速分析”和“完整分析”两个模式。快速分析由用户选择章节或样本范围，只对已处理内容负责；完整分析必须覆盖所选全部原文，不能以抽样冒充全书。完整任务超预算时先建议缩小范围或拆任务，执行中预算不足返回部分结果，禁止静默改成快速模式。

模型分工：通过事实与引用评测的低成本模型优先承担结构化提取；跨章推理与新稿用通过对应质量门槛的模型。质量不达标时只对失败阶段申请升级，展示新增消耗；不默认全部使用最高价模型，也不以降价替代质量验收。缓存前缀、稳定提示词、精简 schema、任务专用参数均需以实际 token 和效果验证。

### 12.3 业务缓存与增量失效

缓存键至少包含用户权限域、规范化内容哈希、章节范围、解析器、提示词、schema、模型版本及分析配置。只有授权有效且键一致才能复用；MVP 不做跨用户原稿或结果缓存共享。缓存命中与节省量单独记录，未实际获得服务商折扣时不得假设存在。

同一本书查看报告、展开引用、调整卡片名称、手动编辑卡片和重新导出，不触发模型。更换新主题仅重跑新大纲和新稿，不重复分析原书。修改某一章仅失效该章提取及依赖它的全局归纳；未变章节复用。修改章节边界导致锚点变化时重新校验，不能为省 token 复用错误引用。模型／提示词升级可保留旧版本结果，重算前展示范围和费用。

生成上下文按目标问题选取相关实体、事件和证据，保存实际 context_manifest 与 token 分项；超限先裁去无关对话、冗余示例和重复内容，再做分层摘要，不裁掉用户的硬约束和必要证据。裁剪不得导致分析覆盖范围被虚报。

### 12.4 预算准入 重试与账本

按单次请求、阶段、任务、用户日额度和平台日预算设置上限，同时保存输入 token、计费输出 token 和金额预算。每次派发前必须满足：已结算成本＋全部在途请求的最大预留成本＋本请求最大成本 ≤ 任务上限，且用户与平台余额充足。各并发 worker 原子预留，不能分别读取同一余额后同时超发。最终账单回填差异，差异异常暂停新派发；不承诺无法控制的第三方费用绝对为零。

内部可在估算执行成本外暂留 20% 重试余量，但该比例不是允许突破上限的缓冲。单阶段自动重试最多 2 次是次数上限，每次仍需预算准入；余额不足时不重试。仅超时、限流等暂态失败退避重试；schema 错误至多一次定向修复且占用重试配额；授权错误、输入超限、内容不支持不盲重试。上游已扣费但未回传结果须保留该物理请求记录，不能假定失败免费。

业务操作账本与物理模型请求账本分开：每个实际 request_id 记录真实费用，每个逻辑任务的收费幂等，防止把真实重试成本丢掉或向用户重复收费。系统自动失败重试不向用户重复收费，内部成本照记；用户改变范围重跑属于新任务，开始前展示消耗。取消停止新派发并释放未使用预留；结算已完成阶段，无法撤销的上游在途成本由内部记录，不产生未预告扣费。

### 12.5 预算算例与成本验证

以下只演示算法，不使用任何厂商现价；假设目标 tokenizer 实测一本书原文为 300000 输入 token，模型输入价为 ¥2／百万 token、计费输出价为 ¥8／百万 token，均无缓存折扣、推理额外费或价格阶梯。实际报价须替换模型、价格和实测 token，不由字数反推固定比例。

| 方案或阶段 | 输入 token | 计费输出 token | 假设模型成本 |
| --- | --- | --- | --- |
| 对照：4 个维度各输入一次全书 | 1200000 | 24000 | ¥2.592 |
| 分层：30 个提取请求，原文加提示开销 | 330000 | 18000 | ¥0.804 |
| 分层：跨章归纳，消费结构化提取结果 | 20000 | 4000 | ¥0.072 |
| 分层：文风采样 | 13000 | 2000 | ¥0.042 |
| 分层方案合计 | 363000 | 24000 | ¥0.918 |
| 后续独立一次新稿生成 | 6000 | 6000 | ¥0.060 |

算例中分析输入下降约 69.8%，模型成本下降约 64.6%；两种方案仅固定输出总量以比较成本，不代表质量等价。¥0.918 不含失败、重试、增量重算、基础设施和售后成本；20% 预留后约 ¥1.102，也不保证足够完成所有重试。该算例不直接用于售卖定价或上线预算。

技术验证需分别实测 5000 字文章、5 万字书、20 万字书和 30 万字上限书，输出真实 token、模型价格版本、分阶段成本、重试成本和缓存命中后的成本。按长度桶报告 P50／P95“单次成功分析成本”和“每个有效创作成本”，以第 14 节质量指标为护栏，禁止仅凭 token 减少宣布优化成功。

价格按服务商现价与 P95 用量更新后确定。单价、私测总预算和单任务硬预算是立项必填项；未确认时仅允许内部限额测试，不开放付费流量。

## 13 指标与埋点

北极星指标：每周完成至少一次“成功分析 → 创建衍生草稿 → 有效使用”的去重用户数。有效使用定义为生成后完成导出、成功导入作品，或正文净修改至少 100 字且持续编辑至少 2 分钟；这是行为代理，不等于内容质量。

| 指标 | 分子／分母与窗口 |
| --- | --- |
| 解析成功率 | 成功可确认的支持文件数／进入解析的支持文件数；按文件类型分层 |
| 分析完成率 | 全部所选范围成功任务数／已进入执行的任务数；按创建 cohort 观察 24 小时，未终态单列，取消另报 |
| 分析到创作转化率 | 成功分析后 7 天内创建衍生草稿用户／成功分析用户 |
| 草稿有效使用率 | 生成后 7 天内有效使用草稿数／成功生成草稿数 |
| D7 复用率 | 首次成功分析后第 7 天再次使用者／已完整观察到第 7 天的首用用户 |
| 时间节约 | 同难度任务同质量门槛的完成时间差／基线完成时间；用实验测量 |
| 成功单位成本 | 总任务成本／成功分析数；并列总成本／有效使用草稿数 |
| Token 与复用效率 | 按阶段和长度桶报告未缓存输入、缓存读取、计费输出、重试 token；业务结果缓存命中数／可复用阶段请求数 |
| 预算与估算误差 | 实际模型成本相对预估的偏差；超预算派发数、未结算请求数、价格差异数；按模型和版本分层 |

事件包括 source_upload_started、source_parse_completed、analysis_requested、analysis_terminal、evidence_opened、card_edited、brief_confirmed、outline_confirmed、draft_generated、draft_validation_failed、draft_effective_used、import_completed、export_completed、source_deleted。

公共字段：匿名 user_id、source_id/version、task_id、draft_id/version、session_id、experiment_group、内容类型、长度桶、模型版本、耗时、成本和错误码。不上传正文、书名、作者姓名、密钥或用户提示词。服务端终态／结算／导入事件为权威，event_id 去重；有效使用按草稿首次达标记一次。

## 14 离线评测与验收

建立至少 60 份有处理授权的冻结素材：20 本故事书（覆盖多视角、倒叙、长篇及别名）、30 篇不同类型文章、10 份异常输入。另设至少 30 个衍生创作任务，测试素材与提示词调优集分开。规模为首轮质量发现集，不足以代表全部体裁。

每份正常素材由两名评审建立关键事实、转折和引用锚点；独立评分后仲裁，记录一致率。文学解释不要求唯一答案，评价是否有依据和合理。生成稿隐藏模型与组别，按素材约束、结构、连贯、文风和可编辑性评分。

| 质量项目 | 建议上线门槛 | 验收方式 |
| --- | --- | --- |
| 解析覆盖 | 所选章节状态可追踪率 100%，无静默截断 | 人工目录对照、异常文件与超限输入 |
| 引用定位 | ≥98% 正确；关键结论无失效锚点 | 正常素材分层抽样至少 300 个引用 |
| 关键事实 | 精确率 ≥95%，关键事件召回率 ≥85% | 人工标注对照；逐类型报告样本量 |
| 解释可支持 | ≥90% 被评为有文本依据且解释合理 | 双人评审至少 100 条解释 |
| 创作可用性 | ≥70% 任务获总体 ≥4/5，且无关键事实编造 | 至少 30 任务；保留分项及分歧 |
| 字数与终态 | 长度／截断识别 100%；不达标不得冒充已验收 | 目标上下限、取消、输出上限与断流 |
| 关键业务安全 | 越权、重复扣费、未经确认覆盖均 0 例 | 权限、并发、幂等、撤销及故障测试 |
| Token 成本控制 | 无超预算派发、重复全文分析和无效缓存复用；请求账本完整率 100% | 上限书籍、并发预留、失败重试、增量重算与模型价格变更测试 |

不得用平均分掩盖权限或数据损坏问题。评测报告同时给原始计数、分层结果和不确定性；样本门槛不作为对外准确率宣传。模型或解析器升级需回归关键案例。

## 15 用户验证与实验设计

发现阶段访谈 8～12 名目标作者，观察其用自己的授权素材完成真实任务，记录现有工具、耗时、信任问题和愿意付费的环节。若用户只需要摘要而不使用衍生创作，重新评估完整闭环的投入。

可用性阶段邀请 20～30 名作者试用 2 周；至少一半完成两次真实任务。访谈和小样本满意度仅用于定位问题，不能宣布留存或转化显著提升。

效果实验以现有 Agent 写作流程为对照，以新工作台为实验组，按用户随机分组，控制任务难度和学习效应；主指标为 7 日有效使用率，护栏为失败率、单位成本与投诉。历史基线缺失，先采集 2 周，再由数据负责人按最小可检测提升、80% 检验功效和 5% 显著性确定样本量；不足时只报告探索性结果。

建议业务继续投入信号为：分析到创作转化 ≥30%、有效使用率 ≥40%、同质量任务时间中位数下降 ≥20%。这些是产品假设，需在实验前冻结；安全与技术门槛必须通过，商业指标不达标则先迭代而非扩大流量。

## 16 上线 灰度与回滚

发布采用 feature flag，资料上传、分析派发、生成与导入分别可控。先内部授权账号，再白名单，再 5%／20%／100%；每阶段至少观察 3 个完整自然日，若样本不足延长，D7 指标只在完整窗口后判断。

上线前置：离线质量门槛通过；预算、模型处理条款与留存规则确认；监控和告警可用；删除演练、队列恢复、导入撤销和旧功能回归通过；运营准备格式限制、失败、消耗和投诉说明。

暂停派发阈值：15 分钟内至少 20 个执行任务且系统失败率 >10%；10 个以上长书样本中 P95 超过目标 2 倍持续 30 分钟；单任务超预算；或发现越权、重复扣费、未经确认覆盖任一例。低流量时由值班负责人按失败样本人工判断，避免小分母误报。

回滚：停止新上传或派发，保留查询与下载；不破坏在途可恢复记录。导入问题单独关闭导入入口。已扣额度核对补偿；数据问题保留操作日志并按版本恢复，不能靠回滚 UI 恢复数据。已独立生成的新稿不依赖功能开关可继续编辑。

## 17 验收场景矩阵

| 编号 | Given 与 When | Then |
| --- | --- | --- |
| AC01 | 超过大小或字数限制的文件上传 | 分析前阻止，展示上限与选章方案，无消耗 |
| AC02 | PDF 为扫描件或文件加密 | 提示不支持，不生成空报告 |
| AC03 | 目录识别错误，用户修改后确认 | 新版本范围正确，旧结果仍指向旧版本 |
| AC04 | 参考正文含创作标签与提示注入 | 仅作为资料处理，不写入用户作品或执行指令 |
| AC05 | 长书第 8 章失败 | 报告显著标部分范围；仅重试该章，账本不重复扣费 |
| AC06 | 倒叙与人物多个别名 | 展示顺序与故事时间分开，可修订实体合并 |
| AC07 | 文章无传播数据或曝光为 0 | 无爆款因果结论，无除零互动率 |
| AC08 | 刷新、断网、取消、worker 退出 | 状态可恢复；取消结果与实际阶段一致 |
| AC09 | 生成正文不足目标或被截断 | 标未验收，保留文字，不自动导入 |
| AC10 | 重复点击导入或同步失败后重试 | 同一操作只产生一组条目，云端状态真实 |
| AC11 | 导入目标在别处已修改 | expected_revision 冲突，保留两版，不覆盖 |
| AC12 | 来源删除后访问引用与导出地址 | 立即拒绝访问、停止任务，新稿仍可独立编辑 |
| AC13 | 用户 A 请求用户 B 的任务／下载／事件流 | 统一拒绝且不泄露内容与存在性 |
| AC14 | 修改新主题但复用已完成分析 | 仅新生成消耗，不重复收整本分析额度 |
| AC15 | 原有章节、人物、大纲与模型设置流程 | 不受入口和 schema 扩展影响，原有回归通过 |
| AC16 | 同书查看、改卡片名称或重新导出 | 新增模型调用和 token 消耗均为 0；仅消耗必要存储与下载资源 |
| AC17 | 同书换新主题或只改一章 | 前者不重跑原书分析；后者只重跑失效章节、依赖归纳和锚点校验 |
| AC18 | 多 worker 并发派发，余额只够一次请求 | 原子预留只允许一次派发；重试与升级同样占预算 |
| AC19 | 上游超时但已计费，或缓存／推理 token 计费不同 | 实际请求费用可追溯，不重复用户扣费；分项与价格版本正确，无重复计算 |
| AC20 | 完整分析超预算，或上下文裁剪后缺关键约束 | 停止或提示调整范围；不静默抽样、不遗漏硬约束后标完整成功 |
