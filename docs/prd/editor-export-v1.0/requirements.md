# NovelAgent 小说编辑与导出产品需求

版本 V1.0　负责人 李晴　日期 2026 年 10 月 28 日

本版将小说编辑页调整为适合长时间写作的紧凑排版，并统一章节在编辑器、文本文件和 Word 文件中的段落结构。用户无需先删除空行就能正常阅读 AI 生成的正文，也能选择导出整本小说或当前章节。本文所列本期功能与代码一并交付。

## 1 背景与问题

当前正文行高接近 1.95 倍，每段额外增加 16 像素下边距，模型输出中的空行又被转换为空段落，导致相邻段落之间显得过于松散。现有 TXT 导出直接删除 HTML 标签，可能把多个段落拼成一段，也不能正确处理全部实体字符。导出只有整本 TXT，且编辑器最后 500 毫秒内的输入可能尚未保存。

## 2 本期目标

- 默认正文清晰、紧凑，正常段落之间不人为插入空白行。
- 为不同屏幕与阅读习惯提供字号、行距、段距和首行缩进选项，并在本机记住设置。
- 提供可撤销的空行整理，保留作者选择的正文内容与基本格式。
- 支持整本小说与当前章节导出，提供 TXT、Markdown 与真正的 Word DOCX 文件。
- 导出前同步编辑器尚未保存的输入，切换章节不丢失最后一段修改。
- Windows Word 中明确设置中文与西文字体，避免依赖主题字体替换。

## 3 范围

本期包括章节编辑器、编辑偏好、段落转换、导出对话框、导出生成器、回归验证和本文档。继续沿用现有小说、章节与本地持久化结构，不要求数据库迁移。

本期不增加 EPUB、云端排版服务、PDF 生成、复杂图片布局、字体嵌入和协同编辑。TXT 面向通用小说阅读器，Markdown 面向继续编辑，DOCX 面向 Windows Microsoft Word。复杂网页样式不作为排版保真承诺。

## 4 默认排版

| 设置 | 默认与可选项 |
| --- | --- |
| 字号 | 默认 16 像素，可选 14、16、18、20 |
| 行距 | 默认 1.6 倍，可选 1.4、1.6、1.8 |
| 段后距 | 默认 0，可选 4、8 像素 |
| 首行缩进 | 默认两字符，可关闭 |
| 段落边界 | 普通段落自然换段，不额外添加空段落 |
| 列表与引用 | 保留结构，列表与引用中的段落不强制首行缩进 |

“排版”入口位于编辑工具栏。设置即时影响显示，不重写正文，不发送模型请求。刷新页面或切换小说后继续使用本机偏好；存储损坏或无法使用时回退默认值。“恢复默认”一次恢复本表设置。

## 5 空行与基本编辑

AI 返回的纯文本按非空文本行转换为段落，连续空行不额外生成空段落。已有富文本不自动删除作者保留的空段落；用户可主动点击“整理空行”，删除仅由空白或换行组成的空段落，保留加粗、斜体、下划线、列表和引用。

整理操作单独进入编辑器撤销历史，可用 Ctrl Z 恢复。每章拥有独立的撤销历史，切章后不会撤回另一章的内容。空正文或列表、引用后的末尾可以保留一个辅助输入段落。整理不得删除图片、分隔线或其他非文本内容，也不得合并两段正文。标题、字号和排版设置不会当作正文内容保存。

工具栏在较窄编辑区域内可换行；工具按钮提供名称及当前状态。正文保持清晰的纸张区域，不因格式工具增加横向溢出。

## 6 保存与编辑连续性

正文继续自动保存，并增加 Ctrl S 即时保存。导出对话框打开前、确认导出前、编辑器失焦和切换章节时，处理当前尚未保存的输入。

若保存前已收到更新版本的 AI 正文，旧输入快照不得覆盖新正文。保存提示表示本机持久化完成，现有云端异步同步机制继续使用。云端确认与跨设备冲突处理不在本期范围内。

## 7 导出流程

用户点击小说顶部“导出”，选择“整本小说”或“当前章节”，选择格式并确认。对话框显示导出范围、格式说明、预计章节数和文件名。未选择章节时不能选择当前章节；没有可导出章节时显示明确说明。

生成过程中避免重复点击。失败时显示原因并保留设置，不关闭对话框；成功发起下载后关闭对话框。所有文件在浏览器本机生成，不上传稿件，不调用模型，不消耗模型 token。

## 8 内容与文件规则

只导出当前小说的章节，按现有章节顺序稳定排序。整本导出包含书名及可选简介；单章导出保留该章在整本中的编号。标题已有“第 N 章”时不重复加编号，文件名移除 Windows 不允许的字符并处理保留名称。

富文本使用实际段落、列表与换行边界读取，正确解码引号、不换行空格等 HTML 实体，忽略脚本和样式内容。纯文本中的小于号与大于号不误当 HTML 删除。导出过程不修改小说和章节。

| 格式 | 输出约定 |
| --- | --- |
| TXT | UTF 8 带 BOM，Windows CRLF 换行；每段一行，章节间清楚分隔；无残留 HTML 标签 |
| Markdown | 书名和章节使用标题；保留段落、加粗、斜体、列表和引用的常用表达；转义正文中的 Markdown 控制字符 |
| DOCX | 使用真实 Office Open XML；A4 页面，正文宋体，西文 Times New Roman，标题黑体；正文 1.5 倍行距、无额外空段，两字符首行缩进 |

Word 章节标题与下一段保持同页，整本导出时每章另起一页；不使用固定行高或浮动文本框。显示排版偏好与投稿文件排版分开，DOCX 使用稳定的导出样式。

## 9 内容保护与兼容

段落读取不执行 HTML，新内容和文件名均作为普通文字处理。Markdown 不携带可执行 HTML，DOCX 不携带宏、外部网页或远程图片。文字支持中文、英文、数字、特殊符号和 Unicode 字符；不声称所有阅读器都支持所有字体或表情。

导出 DOCX 的默认样式、标题样式和实际文字均明确设置中文与西文字体，清除冲突的主题字体引用。交付前检查文档包、字体、段落属性，并使用本机 Microsoft Word 导出页面，逐页检查缺字、乱码、重叠、裁切和分页。

## 10 验收场景

| 场景 | 预期 |
| --- | --- |
| 两段普通正文 | 默认 16 像素、1.6 倍行高、段后距 0 |
| 纯文本含连续空行 | 不额外生成空段落，正文顺序保持 |
| 已有 HTML 含作者空行 | 默认保留，主动整理后才去除，可撤销 |
| 更改排版并刷新 | 偏好保留，正文未被改写 |
| 窄编辑面板 | 工具可换行，排版和保存入口可用 |
| 输入后立即导出 | 文件包含最后输入，不少字 |
| 输入后立即换章 | 原章节最后输入已保存 |
| AI 修改到达时有旧保存任务 | 旧快照不覆盖 AI 修改 |
| HTML 段落和软换行 | TXT 不粘段，不残留标签和实体 |
| 列表与引用 | 导出保留可读结构 |
| 整本与当前章节 | 范围正确，单章编号不重置，不带其他小说内容 |
| 标题已有编号 | 不重复生成“第 N 章” |
| 文件名含非法字符或保留字 | Windows 可保存和打开 |
| TXT 与 Markdown | BOM、换行、编码和 Markdown 转义符合约定 |
| DOCX 字体与布局 | 明确宋体、黑体和西文字体，Word 逐页可读 |
| 空小说、生成失败或连续点击 | 有反馈，不误报成功，不重复下载 |

## 11 实现规划

将阅读偏好、稿件段落读取、导出生成从 UI 中拆出，便于分别验证。Word 生成库按需加载，常规写作不预加载导出代码。修改逻辑继续使用上一版已验证的正文更新机制，不混入历史本地修改。

验收包括自动测试、浏览器实际编辑与下载、导出文件结构检查，以及 Windows Word 页面检查。发现既有构建或 lint 问题时在本次更新记录中说明，不将未完成检查写为通过。
