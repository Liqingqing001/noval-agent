# AI 面板同步与回复显示修复

更新日期：2026-10-25。

本次修复解决 AI 回复有内容却未进入左侧面板，以及回复等待过程不清楚、长文本显示卡顿的问题。同步结果由应用实际写入后生成，模型输出的“✅ 已同步”不再作为成功依据。

## 使用方法

新回复正常完成后会自动同步基本信息、大纲、人物、世界观和章节正文，并显示实际处理的数量。旧消息可点击消息下方的“重新同步到面板”，同名人物、同名世界观更新现有条目。重新同步只处理创作内容，不重复执行删除、修改、合并、拆分等命令。

生成时会立即显示连接状态，随后区分等待正文、模型推理、接收回复和非流式响应，并显示已等待秒数。点击“停止生成”或发生异常后，已经收到的正文保留在会话中，标记为未完成，不自动写入面板。

“已写入本地面板”表示本地状态与持久化写入已执行。现有云端 API 在 store 中异步调用，因此该提示不表示云端请求一定成功。

### 对话内容折叠

成功同步的结构化回复默认显示简短提示和同步结果，不在对话里重复铺开正文。“查看章节 / 大纲 / 人物 / 世界观”可切换到对应面板；需要核对原始回复时点击“展开全文”，展开区域可独立滚动，并可再次收起。

未同步的长回复、旧回复、失败时保留的文字，以及生成中的长内容，超过 600 个字符或 12 行后默认只显示前 240 个字符、最多 6 行的预览；短回复照常显示。生成过程保留状态、字符数和“展开实时内容”，同步失败的回复不会显示查看面板的成功提示。

折叠只影响展示。会话仍保存完整回复，自动同步、上下文请求和导出继续使用原文。

对话面板常驻显示“结构化内容自动同步 · 长回复自动折叠”，生成时显示“生成中，可随时停止”。等待时间与停止按钮仅在请求进行时出现。历史消息如果没有同步结果记录，也会折叠其中的结构化内容，并显示“历史回复未记录同步结果，可重新同步”；不据此推断之前已经同步成功，也不自动重放历史操作。小高度窗口下保留输入和停止按钮，让消息区独立滚动。

### 已定位、尚未修复的章节字数问题

当前工作区的追加提示逻辑使用 `/(\d+)\s*字/` 提取字数，会把“3000-4000字”提取为“4000字”，也不能解析中文“三千到四千字”。系统提示中虽然重复强调字数，生成结束后却没有按目标范围验收正文，章节同步仍会直接标记完成。因此正常结束的短章节也可能被当成已完成章节。

输出 Tokens 是生成上限，不能代替最低字数校验；一次生成多章还会共用同一份输出预算。OpenAI 的限制可能包含不可见生成 Tokens，说明见 [OpenAI Docs：Counting tokens](https://developers.openai.com/api/docs/guides/token-counting)。实际是否发生截断，需要检查对应请求的结束原因和配置。

后续应统一解析阿拉伯数字及中文字数范围，按每章有效正文计数，并将不足目标的章节标记为待补足；补写时需要合并到原章节、限制重试次数，并向用户显示验收结果。本次对话折叠更新未实现上述字数验收或补写流程。

## 解析规则

推荐模型继续使用完整标签。例如：

```text
【世界观】
分类：生存规则
名称：感染传播
内容：通过体液接触传播。
补充内容可以继续换行。
【/世界观】

【角色】
定位：主角
姓名：程砚
性格：谨慎、重视证据
【/角色】
```

兼容处理包括：

- 缺少结束标签：在下一个区块、下一节 Markdown 标题、同步提示行或回复结尾截断当前区块，避免把下一类设定混入正文。
- 同一个块包含多个条目：按重复的姓名或名称拆分，保留对应定位、分类与多行内容；同名记录合并后写入，避免重复创建。
- `【人物】`、`【人物设定】`、`【角色设定】` 与 `【角色】` 等价；`【世界观设定】` 与 `【世界观】` 等价。
- 兼容独立 Markdown 标题，如 `**📝 基本信息**`、`## 人物`、`**🌍 世界观**`，以及加粗字段名、列表符号、英文冒号和 CRLF 换行。
- 基本信息允许 `题材：末世校园 简介：……` 写在同一行，简介也允许另起多行。
- 世界观需要名称和非空内容；缺少名称的人物不创建。章节需要标题和正文，未闭合章节还需超过 50 个字符，避免将很短的残片写入章节。

容错不会猜测任意自然语言的结构。普通讨论、行内引用标签、围栏代码中的示例和没有字段的标题不视为可创建的数据。删除、替换、修改等操作仍使用原来的完整标签解析，不根据 Markdown 标题补全执行。

自动同步仅在模型确认正常完成后运行。超时、取消、输出上限截断或异常断流保留已收到的回复，但不会因为容错规则而自动写入不完整设定。

## 为什么有时迟迟不显示回复

| 原因 | 本次处理 |
| --- | --- |
| 世界观、人物等解析依赖闭合标签，而可同步检测已允许未闭合标签 | 统一提取区块边界，为创作内容增加容错 |
| 旧界面把结束标签直接替换成“已同步”，并未检查写入结果 | 删除格式化过程中的成功声明，改用实际结果与数量 |
| OpenAI 兼容接口或 Gemini 已发出结束原因，但 HTTP 连接仍保持打开 | 收到语义结束事件即完成，保留结束事件携带的最后一段文字并释放 reader |
| 生成期间每个小分片都会重跑 Markdown 渲染与平滑滚动 | 首片立即显示，后续最多约每 80ms 刷新一次；流式正文使用文本显示，结束后渲染 Markdown；缓存历史 Markdown，流式滚动使用即时滚动 |
| 模型先返回推理事件、接口非流式返回，原界面没有首字之前的状态 | 显示明确阶段与等待时间，不展示推理文本 |
| 最终文字由 React state 与 effect 回填 ref，存在异步时序问题 | 完成回调直接接收服务层最终字符串，清除待刷新的计时器 |
| 最新用户请求既作为历史消息又作为增强消息发送 | 历史上下文只包含发送前的消息，本次用户请求只发送一次 |

OpenAI 的 `finish_reason` 说明见 [OpenAI Docs：Chat Completions streaming events](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events)。这里只消费文本结果，不等待额外的 usage 尾帧。

模型服务排队、推理耗时、网关缓冲、网络质量，以及每次请求携带较长章节上下文，也可能增加首字等待。本次验证使用模拟网络，不能据此确定某个实际服务商的延迟原因。状态显示能帮助区分等待服务和接收正文；未发送推理事件时不会猜测模型正在推理。非流式请求只能等待完整结果，状态提示无法把它转成真正的流式服务。

## 验证与维护

在仓库根目录运行：

```powershell
npm run test:sync
npm run test:models
npm run build
```

- 解析与 store 集成：12 项测试，覆盖漏闭合、多条内容、多行字段、用户示例、别名、重复同步、临时存储持久化与命令不重放。
- 模型服务：24 项测试，包括连接保持打开时及时结束、最后分片保留、推理阶段提示和非流式识别，以及四类协议原有回归。
- 浏览器冒烟：在独立临时上下文中模拟模型响应，确认基本信息、1 个人物、2 条世界观写入；再次同步不增加重复记录；停止生成保留部分文字且世界观数量不增加。验证了首字前的推理状态与本次请求不重复发送。
- 前后端生产构建通过。现有生产包仍有体积提示；`AgentPanel.tsx`、`autoSync.ts` 中尚有既存 lint 错误，本次新增解析、状态与服务代码的定向 lint 通过。

实现入口：`structuredContent.ts` 负责可独立测试的解析，`autoSync.ts` 负责写入与命令处理，`syncFeedback.ts` 负责结果文案，`ModelService` 负责协议事件，`AgentPanel` 与 `GenerationStatus` 负责显示与取消。
